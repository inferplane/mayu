# internal Module

## Role
Private gateway internals — everything that is not a provider or a public package.
Packages are leaf-oriented to avoid import cycles (`principal`, `metrics`, `governance`
are leaves that others depend on).

## Invariants
These are the facts in this module worth knowing before touching it — the rest is
in the code and in `docs/decisions/`.

- **Pre-check before billing, settle after.** `on_exceeded` block wins on tie (`governance/`).
- **Cost is integer microUSD, never float.** Round-half-even via `math/big`.
- **`count_tokens` must never return non-200.**
- **Money units cross a boundary exactly once:** wire policy documents are milliUSD
  (1000 = $1, operator-facing); `policy/` converts to internal µUSD (×1000, exact) and
  nothing downstream re-converts. Settling coarser reopens ADR-030's zero-cost bug class.
- **Secrets never enter a DB-backed store** (`providerstore/`, `policystore/`) — only refs.
  A `policystore` constructor error is a hand-written string that never wraps the
  underlying pgx error, which can embed the DSN (and a password).
- **`key_id` never reaches a `/metrics` label**, but may reach a webhook payload body
  (`alert/`) — a label is cardinality-unbounded exposure, a payload body is not.
- **A raw user id never reaches a `/metrics` label** (`keystore.Principal.Owner`, an
  admin-supplied free string or an OIDC `sub`) — the same unbounded-cardinality bar
  `key_id` sits behind: no user-labelled series, no `SetBudgetUtilization` user
  variant, and no `alert/` dedup map keyed on a raw user id (`fired`/`firedKey` are
  unbounded in-memory maps; a `firedUser` would be a leak). A webhook payload body
  MAY carry one (`Fire.KeyID` is the precedent) — the restriction is metric
  cardinality and unbounded dedup maps, not exposure.
- Keep `principal`, `metrics`, `governance` import-cycle-free — widely depended on.
- Metric labels are config-bounded; never label with raw client input (`_rejected`
  sentinel on pre-resolution rejects).
- A policy from `policy/`/`policystore/` can only **narrow** a key's allow-list or
  budget, never widen one already set elsewhere (`router.SetPolicyGate`).
- RBAC re-check after routing: `router.FilterModelAllowed`/`FilterRegions` must run
  right after `ResolveChain` in every ingress handler — the router has no `Principal`
  in scope, so a model-fallback or region-filtered target appended *after* the
  original allow-list check is not itself RBAC-checked until the handler does it.
  This includes BOTH `count_tokens` handlers (previously they re-checked only
  pre-routing, so a region-promoted cross-model fallback's upstream could receive
  the caller's body — review/fable5 C3), and `FilterModelAllowed` must run BEFORE
  the region/ingress filters: it derives "primary" from `chain[0].Model`.

## Key Packages
- `server/` — HTTP data plane + admin plane. Ingress handlers: `anthropicapi/`, `openaiapi/`, `bedrockapi/` (ADR-024); `usageapi/` self-service `GET /v1/usage` (ADR-021); `authapi/` opt-in CLI login (ADR-028); `adminapi/`, `configapi/`, `auditapi/`, `analyticsapi/`; `adminui/` embedded console (ADR-001, SSO ADR-026, i18n ADR-027). A mid-stream upstream failure surfaces as a wire-appropriate error frame (SSE `error` event / eventstream exception), never a silent truncation, and the audit record is marked `partial: true`. **Every observability sink sees the same settled usage.** A partial stream's usage is settled, so it must also be `observeTokens`'d — metering only the clean path left `gen_ai_client_token_usage_total` below the budget spend, the audit ledger, and the usage windows on every interrupted stream. `recordSpanSettled` (not `recordSpanResponse`) is the span call at the three COMMITTED sites; `recordSpanResponse` stays for the terminal pre-commit rejects, where there is no usage or cost to report.
- `router/` — model→provider resolution (`ResolveChain`), priority fallback, per-provider circuit breaker. `Canonical`/`Allows` (ADR-021) canonicalize model aliases before RBAC. `ResolveModel` (ADR-029) substitutes an unrouted model via `model_fallbacks` or same-family default before the allow-list check. `FilterRegions`/`FilterModelAllowed` are the pure RBAC re-check functions ingress handlers must call after `ResolveChain` (see Invariants). `SetPolicyGate` (ADR-033) ANDs an optional GovernancePolicy check onto every `Allows` decision. `SetTierGate`/`SubstituteTier` (ADR-041) substitute an ALREADY-routed model per an active budget tier — a distinct call from `ResolveModel`, since that method's contract ("a configured model is never second-guessed") and its lack of a `Principal` are both wrong for a cost-triggered, RBAC-checked substitution; fires only when the original passes `Allows` and only if the target also does, so it can never widen access or turn into a denial.
- `governance/` — `Governor` (`PreCheck`/`Settle`). `SetLeaseGate` (ADR-034) checks a budget lease first in `PreCheck`, denying 402 before any counter is charged. `UsageOf` (ADR-021) is the read-only companion behind `GET /v1/usage` — no debit, no state change. `SetTeamLookup` (ADR-016) prefers a DB team record over the static config map. `SetBudgetNotify`/`SetKeyBudgetNotify` (ADR-017) fire post-debit alert hooks. `Settle` takes the exact estimate `PreCheck` charged and trues up TPM against actual usage via `AdjustRate` (ADR-039), and debits the daily quota by total tokens including all three cache tiers — not `Input+Output` alone. `PreCheck`/`Settle` also enforce a calendar-DAY budget beside the monthly one, against a separate counter with its own store key, block wins on tie via whichever window resets soonest; `SetBudgetTimezone` is the `budget_timezone` seam (nil = UTC) and now anchors BOTH calendar windows — the month boundary honours the operator timezone too (ADR-042), no longer the day's midnight only. `PreCheck`/`Settle`/`UsageOf` take a `Subject{Team, KeyID, User}` value replacing the two leading string args (ADR-042 Phase 3) — each ingress builds it with its own `subjectOf`, same deliberate per-package duplication as `keyPolicyOf`, keeping this package a leaf. `SetUserLookup`/`UserPolicy` add per-USER budget: budget only (no RPM/TPM), ONE `on_exceeded` for both windows (block wins on tie, collapsed in the gateway closure). The user counter's id is `team + "/" + user` (`userBudgetID` — "/" is safe because `adminapi.validateTeamName` forbids it in team names, so the split point is unambiguous); a user-ONLY subject therefore counts separately per team, accepted in ADR-042. `GET /v1/usage` gains `user_budget`/`user_budget_day` (appended, omitempty).
- `keystore/` — virtual-key `Store` (SQLite), `Principal`, RBAC `Allows()`. `TeamStore` (ADR-016) is the `teams` table (allow-list, RPM/TPM, budget, guardrail override ADR-019, region lock ADR-020). `KeyEnsurer.EnsureKey` (ADR-023) upserts a caller-supplied plaintext so a config-declared key survives a wiped store. `ErrKeyExpired` (ADR-028) is distinct from `ErrKeyNotFound` so an expired CLI-minted key gets a different 401 message — still 401 either way. Both `teams` and `keys` carry a `budget_usd_micros_per_day` column (calendar-day µUSD cap, 0 = unlimited; ALTER-migrated so pre-existing rows read back 0).
- `audit/` — single-writer hash-chain writer, WAL, `verify.go`. `audit/s3anchor/` is opt-in S3 Object Lock anchoring (ADR-012). `Record.BodyRef`/`RecordRef` (ADR-018) are appended at the struct end (omitempty) so mixed-version chains still verify byte-identically. `UsageRef.CacheCreation{5m,1h}InputTokens` follow that same append-at-the-end rule: `CacheCreationInputTokens` stays the flat TOTAL for existing consumers while the two tiers make the 1.25x/2x billing reproducible from the ledger alone. `RequestRef.ModelSubstitutedFrom` (ADR-041, appended at that struct's end, same rule) carries the client's ORIGINAL requested model when a budget tier substituted it — `ModelRequested` by then already holds the model actually served. `WithSubstitutedFrom`/`SubstitutedFrom` thread it via request context from the ingress substitution point down to the audit call.
- `bodystore/` — opt-in encrypted request/response body capture (ADR-018), OUTSIDE the audit chain. Envelope AEAD; `Fetch` is fail-closed (any decrypt/miss → 410 tombstone, never plaintext). SQLite/Postgres backends; key rotation via `bodies rewrap-key`.
- `analytics/` — derived usage read-model backing `GET /admin/logs`; `pgstore/` is the shared-Postgres backend (ADR-015).
- `pricing/` — integer microUSD table, round-half-even. **ADR-030**: rate key is `(config provider name, UPSTREAM model id)`, never the canonical ingress name — the single most common way to end up billing 0. `HasRate` backs both boot validation and the runtime guard, so they can't drift apart. Cache rates derive from the input rate (0.1x read / 1.25x 5m-write / 2x 1h-write) unless explicitly overridden. A `0/0` override without `"free": true` is unpriced, not free — the row is left out of the table entirely, so `HasRate` is false and every unpriced path engages; `free: true` is the ONLY way to declare a genuinely zero-cost model.
- `limiter/`, `budget/` — in-memory two-phase governance stores with injectable clocks. `LimiterStore.AdjustRate` (ADR-039) is a post-hoc balance correction on a token bucket, not a second refill — it never floors a debit at zero (a bucket driven negative stays blocked until real refill time repays it). Per-instance state (see ADR-013 in Design Debt below). `budget.Window`'s calendar kinds (`CalDay`/`CalMonth`) get separate counters via `budget.Key`'s tag-first layout (`budget:day:...` vs `budget:month:...`), which is what keeps the day and month windows from sharing a bucket. `CalendarMonthIn(loc)` mirrors `CalendarDayIn` so the month window honours `budget_timezone` too (ADR-042); `Tag()` ignores `Loc`, so switching the operator timezone moves a counter's boundary, never its store-key identity. `budget.Memory` is now bounded (ADR-042 Phase 3): an amortized expired-entry sweep every 256 `cur` calls (`sweepEvery`) plus a `maxEntries` fail-closed cap (`defaultMaxEntries` ~100k) — a refused NEW key makes `Check` return `Block`, never a silent `Allow`, and rolling an EXISTING key over its window boundary is never refused. `Rejections()` is the operator seam; deliberately no metric behind it (a user-dimensioned label is forbidden — see Invariants). `ScopeUser` is now used: the user budget counters (`budget:day:user:team/sub`) are its first consumer.
- `alert/` — budget-alert webhook emitter (ADR-017). Fire-and-forget JSON POST on each newly-crossed utilization threshold; per-team and per-key paths dedupe independently. (ADR-041 designs a `tier_activated`/`tier_deactivated` event on this same emitter; not yet wired — see roadmap.)
- `metrics/` — Prometheus registry + GenAI collectors + nil-safe hooks. `ObserveModelSubstitution` (ADR-041, `inferplane_model_substitution_total{team,from_model,to_model}`) is labeled only from policy-declared values, same cardinality posture as `ObserveFallback`.
- `tier/` — ADR-041 budget-tier model substitution primitives, shared by `controlplane/` (judges) and `proxy/`/`cmd/mayu` (applies). `Table` is the request-path per-team substitution map (`Get`/`Set`, mirrors `proxy.LeaseTable`'s shape); a cross-rule key conflict resolves to the higher `ThresholdPercent` (deeper budget pressure), ties broken by `(policy, rule)` name for determinism. `Latch` makes tier activation monotone within one budget window — it never de-escalates on a dip, only resets when `WindowKey` (interim calendar-month-UTC; a stand-in for roadmap item ②'s eventual control-plane-computed `windowID`) changes. A leaf package: no import of router/server/governance, only `policy` for the wire `ActiveTier` shape.
- `openai/` — OpenAI ⇄ canonical conversion. `ReadChatSSE` also synthesizes the Anthropic frame lifecycle the OpenAI wire has no equivalent for (message_start/message_stop, implicit text openers, per-block closes) — including a terminal stop-bearing `message_delta` when the upstream ends a stream with neither a `finish_reason` nor a usage-only chunk, since `message_delta` is the only frame carrying `stop_reason` and a client otherwise cannot tell a completed turn from a truncated one. Exactly ONE is synthesized: any upstream message-level frame suppresses it, because a consumer may treat the first `message_delta` as end-of-message.
- `adminauth/` — admin-plane OIDC identity leaf (ADR-004): shared bearer-shape predicate, groups→team mapping, go-oidc verifier.
- `live/` — reloadable topology (providers + routes + pricing) behind one atomic `Holder` (ADR-006). `BuildState` also runs pricing-coverage validation (ADR-030): `on_missing: block` refuses to boot on an unpriced route; `allow` (default) logs loudly and continues. `Canonical`/`FallbackFor` back the router's alias and model-fallback resolution. `BuildStateWith(cfg, Deps)` (ADR-040) is the injection seam the gateway uses to hand a `providers.CredentialSource` to provider construction; `BuildState(cfg)` is `BuildStateWith(cfg, Deps{})`. `Deps` is a pure pass-through — `live` must not gain dependencies of its own, and the structural import-guard test enforces that.
- `providerstore/` — opt-in DB-authoritative provider/model topology (ADR-008). Refs only, no secret column. UI writes build-once-swap-once under one `reloadMu`.
- `config/` — config loading + secret-ref resolution (inline secrets rejected). OIDC block validation; `CLILogin` requires a client ID distinct from the console's own (ADR-028). `ModelFallbacks`/`ModelFallbackFamily` (ADR-029) validated at both the file-load and UI-write paths. A bedrock provider's `auth.mode` is a CLOSED set (ADR-040 fail-closed invariant #2 — before it, any unrecognized string silently meant "default", so a typo deployed the bypassable local-IAM posture); the check lives in `ResolveProviders` precisely because that is the one path BOTH the file load and the ADR-008 UI write go through. `auth.mode: "broker"` additionally requires a `control_plane` block, a `broker_token_ref` resolving to a value DIFFERENT from `token_ref`, and an https-or-loopback control-plane URL. `server.max_request_bytes` (C9) bounds every data-plane request body — default 64 MiB, negative rejected at load — and is DISTINCT from `audit.log_bodies.max_body_bytes`, which caps a per-record captured body, not the ingress read; the name difference is deliberate. `models.<name>.context_window` (tokens, input+output, 0=unknown) is the operator-declared model context limit: advertised in GET /v1/models on both wire shapes (a gateway extension — clients otherwise assume a default window for unrecognized ids) and enforced as an estimate-only fast-fail 400 naming both numbers in the three generation ingresses, before PreCheck (the upstream's own rejection reaches clients as an opaque scrubbed ValidationException); count_tokens never pre-flights (never-non-200). File-config only for now — the ADR-008 UI write path does not carry it. `control_plane.require_sync` (+ optional `max_policy_age`, review/fable5 §08 B2/B3) flips the data plane fail-closed on control-plane reachability: governed routes 503 (count_tokens/`/v1/models` exempt) and `/readyz` is not-ready until the first successful heartbeat, and again once the last success is older than `max_policy_age`; `max_policy_age` without `require_sync` is a load error (a silently ignored knob is the failure mode this repo refuses). Default false keeps the documented fail-open posture.
- `principal/` — request-scoped principal context (leaf, breaks import cycles).
- `tracing/` — opt-in OpenTelemetry seam (ADR-011): OTLP **trace** exporter + GenAI-semconv spans + W3C propagation + `trace_id` in audit. No-op by default. Traces are the ONLY OTLP signal — metrics are Prometheus exposition (`metrics/` is the one registry; a second OTLP metric SDK would double-instrument and drift) and logs are the audit chain, not OTLP. Attributes semconv has no name for take an `inferplane.` prefix, never an invented `gen_ai.*` one: `SetUsageDetail` (cache read / 5m / 1h write, zero tiers omitted), `SetCost` (integer µUSD + `pricing_missing`, always paired — a 0 with the flag is "unpriced", without it "free"), `SetPartial`. No secret, `key_id`, or raw client input ever reaches a span attribute.
- `filter/` — request-transform filter seam (ADR-009): `RequestFilter` interface + registry. Concrete filters live under `plugins/<name>/` and register via blank import.
- `policy/` — rule + budget-lease schema shared by BOTH binaries (ADR-031/032/033) — the single source of truth. Converts `api/v1alpha1` wire docs and explicitly rejects anything unsupported (`UnsupportedError`, reported upstream, never silently ignored). Subjects (`team`/`user`) are equal citizens; most-restrictive-wins on multi-match. Exactly one rule kind per rule; `failurePolicy` required, no default. A `rate`/`budget` rule may set `unlimited: true` instead of a numeric limit — an explicit, auditable "no cap" (ADR-039) that internally still produces the pre-existing zero-value sentinel every consumer treats as unlimited; `mergeTeamLimits` and the controlplane lease ledger both give it its own branch so it can never narrow, widen, or silently overwrite a real limit set by another rule. The local file channel (ADR-033) rejects the routing rule's cache-affinity half and user-subject rate rather than accepting and ignoring them; the routing rule's `budgetTiers` half (ADR-041) and user-subject BUDGET rules (ADR-042 Phase 3) ARE enforceable — `Routing` is exactly one of `Affinity` or `BudgetTiers`. `Store.SetRoutedAndPriced` installs the ADR-041 apply-time check that a substitution TARGET is routed+priced on this data plane (nil skips it; the control plane's `LoadWirePaths` deliberately never installs one, same posture as its skip of `checkEnforceable`). `BudgetRule.period` (ADR-042) selects a budget rule's calendar window — `CalendarDay` | `CalendarMonth`, empty = CalendarMonth, so every pre-existing document keeps its meaning; a day cap plus a month cap are TWO rules in one policy (`hardCap`/`failurePolicy`/`lease`/`adminContact` are per-rule, and so is the lease ledger row), and `period` must not be combined with `unlimited`. `TeamLimits` folds the day window independently of the month (`BudgetMicrosPerDay`/`BudgetDayHard`/`AdminContactDay`) — most-restrictive-wins is computed per window, and `unlimited` is window-agnostic, touching neither. `UserLimits`/`mergeUserLimits` (ADR-042 Phase 3) do the same for user-subject BUDGET rules — budget only, no RPM/TPM; most-restrictive-wins per window via `narrow`, `unlimited` window-agnostic here too — and `Store.UserLimits(team, user)` folds a user-only subject together with the (team, user) one. `checkEnforceable` is now rate-only for the subject restriction: user-subject budget is enforceable, user-subject rate still is not (needs a rate-share model).
- `policystore/` — opt-in Postgres-authoritative GovernancePolicy store for `inferplaned` (ADR-038). The document, not the rule, is the CRUD unit. File-loaded set = seed, DB = authoritative once seeded (marker-gated, never row-count).
- `controlplane/` — `inferplaned`'s distribution core (ADR-034): `POST /v1alpha1/sync` is one heartbeat (policy pull + consumption report + lease renewal + rejection report + ADR-041 active-tier judgment). Budget-lease ledger is in-memory; its rows carry the rule's budget `period` and each grant is stamped with it (ADR-042), so a day rule and a month rule lease independently — a grant or report without a period reads as CalendarMonth, the meaning the wire had before windows existed. `(*ruleLedger).totals` is the one Σspent/Σoutstanding computation the lease-grant loop and the ADR-041 tier judgment both call, so they can't compute utilization differently by accident. `tierLatch` (`*tier.Latch`) is a `Server` field, NOT rebuilt in `applyWire` — it must survive a policy edit the same way ledger spend/allowance does, or every reload would silently un-latch every team mid-window; only rules that no longer exist get their latch state forgotten. A USER-scoped budget rule gets NO ledger row and NO grant (`applyWire` skips it, ADR-042 Phase 3): the row is team-keyed and its clamp would throttle the whole team to one individual's limit — per-user budget is per-data-plane in-memory, same posture as `rate`. `applyWire` (ADR-038) is the one install path both the file loader and the DB loader go through, so ledger semantics never diverge by source. `policies.go` mounts read/write policy routes behind the same auth as sync (ADR-038 accepted limitation: no separate write authorization). `broker.go` (ADR-040) is the credential broker: `POST /v1alpha1/credentials` mints ≤1h STS sessions (`DurationSeconds` 3600 — role chaining's hard cap, since inferplaned's own task role is already assumed) tagged/named with the sanitized dataplane id. It is a `BrokerServer` with its OWN token and its OWN `authnBroker` check — deliberately NOT the shared `authn`, which also accepts verified OIDC console identities, and a browser SSO session must never mint AWS credentials; a JWT-shaped bearer is 403'd before any comparison. Mounted only when `INFERPLANED_BROKER_ROLE_ARN` is set (unset ⇒ 404, byte-identical behavior). STS sits behind the narrow `stsAPI` interface so tests need no AWS; an STS failure is a 502 with a FIXED body (the error text can name the role ARN, so it goes to the log only); a refused `SourceIdentity` (inherited from the task-role session) retries ONCE with session tags alone.
- `proxy/` — mayu's control-plane `Syncer` (heartbeat client), `LeaseTable` (the `Governor` lease gate: hard cap + expired/zero allowance fails closed), and `Syncer.Tiers` (`*tier.Table`, ADR-041) applied from `resp.ActiveTiers` alongside `Leases` — a control-plane outage keeps the last-received tier state, same posture as leases/policies. `LeaseTable` is keyed `(team, period)` and the gateway clamps each budget window against its OWN lease (ADR-042); `Syncer.GovernanceReady(maxAge)` is the request-path gate behind `control_plane.require_sync` — not-ready before the first successful heartbeat and once the last one is older than maxAge; `lastSuccess` is published AFTER the set is applied so a ready observer never sees an unpopulated store. `Syncer.SpentOf(team, period)` reports per-window spend — window-blind reporting would starve a daily rule's grant to zero once the month's spend passed its limit, because the control plane computes remaining = limit − reportedSpend. The sync report loop also skips user-subject rules (ADR-042 Phase 3): they hold no lease, so there is nothing per-user for a consumption report to carry. `credentials.go` (ADR-040) is `CredentialFetcher`, the broker client and mayu's implementation of `providers.CredentialSource`: a channel separate from both the heartbeat and the usage push, sharing only the base URL and carrying the DEDICATED `control_plane.broker_token_ref` bearer. Secret hygiene is a hard requirement here, and the three error policies differ on purpose — a non-2xx yields status code + a fixed string with the body drained unread, a decode failure yields a fixed string with NO `%w` (`time.Time`'s parse error echoes the raw value twice, and `expiration` is a field the response carries), and only a transport error wraps with `%w` (a `*url.Error` has no credential material).
- `cache/` — `VolatileStore` interface for in-memory-only payload caching / cache-affinity routing. **Not implemented** — no importers today; the routing rule's `Affinity` half exists in the wire schema ahead of this package (its `BudgetTiers` half, ADR-041, does NOT depend on this package and is implemented).
- `telemetry/` — usage wire types + window `Collector` + `Aggregator` (memory/postgres/durable), live (ADR-036). `proxy.UsagePusher` drains it to `inferplaned` on a channel separate from the enforcement-critical sync heartbeat.

## Design Debt
Worth knowing before assuming a caveat is temporary:
- **Multi-replica HA is designed, not built (ADR-013, still Proposed).** `keystore`/`providerstore` are SQLite-only; `limiter`/`budget` are memory-only; there is no Redis/Valkey dependency anywhere. Every "per-instance state" note above is a standing limitation, not a transitional one.
- **`cache/` (VolatileStore) is unimplemented** — see above.
